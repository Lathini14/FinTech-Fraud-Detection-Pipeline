# EC8207 Applied Big Data Engineering
## Mini Project — FinTech Fraud Detection Pipeline
**Scenario 2: Banking & Security | Lambda Architecture**

---

## Project Overview

This project implements an end-to-end **Lambda Architecture** data pipeline for real-time fraud detection in a digital wallet system. The pipeline ingests synthetic credit card transactions, detects fraud in real-time using Apache Spark, stores results in PostgreSQL, and generates scheduled reconciliation reports via Apache Airflow.

### Two Fraud Detection Rules
| Rule | Condition | Action |
|---|---|---|
| High Value | Transaction amount > $5,000 | Flag immediately → `fraud_alerts` table |
| Impossible Travel | Same user in 2 different countries within 10 minutes | Flag immediately → `fraud_alerts` table |

---

## Architecture

```
Python Producer
      │
      ▼ JSON stream (every 0.5s)
Apache Kafka (topic: transactions, 3 partitions)
      │
      ▼ consume (micro-batch every 10s)
Apache Spark Structured Streaming
      │
      ├──► fraud_alerts (PostgreSQL)  ──► Analytic Report
      │
      └──► validated_transactions (PostgreSQL)
                    │
                    ▼ every 6 hours
             Apache Airflow DAG
                    │
                    ├──► Parquet files (Data Warehouse)
                    └──► Reconciliation Report (CSV)
```

---

## Tech Stack

| Component | Technology | Purpose |
|---|---|---|
| Ingestion | Apache Kafka 7.4.0 | Real-time message streaming |
| Stream Processing | Apache Spark 3.4.0 | Fraud detection micro-batches |
| Orchestration | Apache Airflow 2.8.0 | Scheduled ETL every 6 hours |
| Database | PostgreSQL 15 | Hot storage for transactions |
| Data Warehouse | Parquet files | Cold storage for validated data |
| Infrastructure | Docker Compose | Container orchestration |

## Setup & Running

### Step 1 — Start all Docker services
```bash
docker compose up -d
```
Wait about 60 seconds, then verify all 4 containers are running:
```bash
docker compose ps
```
You should see: `zookeeper`, `kafka`, `postgres`, `airflow` — all with status `Up`.

---

### Step 2 — Create the Kafka topic
```bash
docker exec -it fraud-pipeline-kafka-1 kafka-topics --create --topic transactions --bootstrap-server localhost:9092 --partitions 3 --replication-factor 1
```
Verify it was created:
```bash
docker exec -it fraud-pipeline-kafka-1 kafka-topics --list --bootstrap-server localhost:9092
```

---

### Step 3 — Start the Producer (Terminal 1)
```bash
python producer/producer.py
```
Expected output:
```
Producer started. Sending transactions every 0.5s...
Sent: user_4  | $234.50  | US
Sent: user_11 | $7800.00 | JP   ← fraud injection
Sent: user_7  | $145.20  | AU
```

---

### Step 4 — Start Spark Streaming (Terminal 2)
```bash
python spark_job/fraud_detector.py
```
Expected output:
```
DB tables ready.
Spark streaming started. Watching for fraud...
Batch 0: 14 validated | 2 fraud flagged
  [FRAUD] user_5 | $9200.00 | UK | High value transaction: $9200.0
  [FRAUD] user_3 | $450.00  | AU | Impossible travel: US -> AU within 4.2 mins
```

> **Note:** WARN messages about NativeCodeLoader and BlockManagerId are normal on Windows. As long as you see `Batch X:` lines, the pipeline is working correctly.

---

### Step 5 — Trigger the Airflow DAG

1. Open your browser and go to: **http://localhost:8080**
2. Login with username: `admin` / password: `admin`
3. Find the DAG named `fraud_reconciliation`
4. Click the **toggle** to enable it
5. Click the **▶ Trigger DAG** button to run it manually

The DAG runs two tasks in sequence:
- `export_to_parquet` — exports validated transactions to `data/validated_transactions.parquet`
- `run_reconciliation` — generates `data/reconciliation_report.csv`

Both tasks should turn **green** when complete.

## Stopping the Pipeline

Stop the producer and Spark job with `Ctrl+C` in each terminal, then stop Docker:
```bash
docker compose down
```

---

## Resetting the Database

To start fresh with a clean database:
```bash
docker exec -it fraud-pipeline-postgres-1 psql -U admin -d fraud_db -c "TRUNCATE TABLE fraud_alerts; TRUNCATE TABLE validated_transactions;"
```

Also clear the Spark checkpoint:
```bash
# Windows
Remove-Item -Recurse -Force "C:\tmp\spark-checkpoint" -ErrorAction SilentlyContinue
New-Item -ItemType Directory -Force -Path "C:\tmp\spark-checkpoint"
